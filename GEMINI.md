# ChromiumOS Infra Recipes - GEMINI.md

This document provides guidance for developing and maintaining recipes within the `chromiumos/infra/recipes` repository. It outlines key concepts, best practices, and development workflows to ensure high-quality, maintainable, and testable recipes.

## Overview

The `chromiumos/infra/recipes` repository contains the recipes that define the workflows for various ChromiumOS infrastructure tasks. These recipes are written using the LUCI Recipe framework, a powerful tool for orchestrating complex build processes.

## Key Concepts

*   **LUCI Recipes:** A framework for defining build workflows as Python scripts. Recipes describe a sequence of steps, each involving the execution of subprocesses, manipulation of files, and interaction with LUCI services.
*   **Recipe Modules:** Reusable components that encapsulate specific functionality (e.g., interacting with Git, managing files, executing shell commands).
*   **Properties:** Input parameters passed to a recipe, allowing for customization of behavior.
*   **Steps:** Individual actions performed by a recipe, often involving the execution of a subprocess.

## Getting Started

### Understanding the Repository Structure

*   **`recipes`**: Contains the Python files defining the recipes themselves.
*   **`recipe_modules`**: Contains reusable modules with specific functionalities.
*   **Expectation files**: Files generated by recipes tests for both recipes and recipe modules, for example `recipes/cq_orchestrator.expected/basic.json` and `recipe_modules/src_state/examples/workspace_path.expected`
*   **`.recipes_deps`**: A hidden directory managed by the `recipes.py` script. It contains the checked-out source code of all recipe dependencies listed in the `infra/config/recipes.cfg` file, such as the `recipe_engine` itself and other external recipe module repositories. This folder is necessary for running or testing recipes locally, as it provides the required dependency code. This directory should NOT be committed to the repository.

### Testing Changes

Run `./recipes.py test train` to test changes to the recipes. This may generate changes in the expectation files.

## Development Tips

### Running Tests
*   **PATH Dependency:** The `recipes.py` script requires `cipd` (from `depot_tools`) to be in your `PATH`. If it is not globally available, you can use the version in the workspace (relative to `infra/recipes` directory):
    ```bash
    PATH=$(realpath ../../src/chromium/depot_tools):$PATH ./recipes.py test train
    ```
*   **Filtering Tests:** Running all tests can take time. You can filter to a specific recipe using the `--filter` option:
    ```bash
    ./recipes.py test train --filter <recipe_name>
    ```

### Recipe Engine Gotchas
*   **Exception Attributes:** When catching exceptions raised by recipe modules (e.g., `api.cipd.Error`), custom attributes like `message` might not be available on the exception object. Use `str(e)` or `e.args` to inspect the error content.
